## Analysis of Misses and Errors

### What did not recur from run 1 (FP 2)

The `get_raw_output` source-name ambiguity that gave run 1 its second false positive is still in this build: the rm1 extraction agent's first reads were `tsk.fsstat`, `tsk.filelist`, `tsk.masquerade` and `tsk.timeline` by bare name with `after_id: 0`, and `tsk.masquerade` returned rm2's 17 rows to the rm1 agent, exactly as before. The difference is what the model did with them. Run 1's rm1 agent wrote "massive file masquerading on rm1!" and gave RM1 a FAT32 partition; this run's rm1 agent wrote "Now let me examine the RM2 masquerade data more closely" and submitted `Massive File Extension Masquerading on RM2` from the rm1 context, which the cross-system phase kept as the RM2 finding. RM1 is an exFAT stick with one filesystem in every place the report describes it, RM2 carries its own label, files and deletion, and items 3, 4, 7 and 15 are scored on the right devices. The ambiguity is unfixed and the outcome this time is the model's, not the harness's; the run-1 recommendation to qualify source names by image stands.

### USB identification retrieved, not reported (items 3, 4, 12)

The catalog summary reads "Registry queries confirmed Eastern Standard Time timezone, OS install date 2015-03-22, SanDisk Cruzer Fit USB device, and last shutdown 2015-03-25T15:31:05 UTC", `USBSTOR` was queried twice and the counter-analysis phase found "17 USB/USBSTOR registry hits". The three items are at the same status as run 1 for the same reason, with the dual-partition error gone and a wrong first-detection date added.

### CCleaner (item 14)

The same false positive as every run in the series, now in its most categorical form: "successfully destroyed", "destroyed relevant browser and application logs", "successfully destroying browser history databases".
