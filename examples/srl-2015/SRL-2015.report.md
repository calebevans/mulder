## Investigation Report

# Stark Research Labs Domain Compromise — Investigation Report

## Background

This investigation examines a multi-system intrusion targeting Stark Research Labs, a research organization operating within the shieldbase.local Active Directory domain. The forensic evidence encompasses four systems spanning the organization's Windows infrastructure: a domain controller running Windows Server 2008 R2 (10.3.58.4 / 10.3.58.9), a Windows 7 32-bit workstation designated "nromanoff" (10.3.58.5), a Windows 7 64-bit workstation designated "nfury" (10.3.58.6), and a Windows XP 32-bit workstation used by "tdungan" (10.3.58.7). Evidence was collected via memory dumps, disk images, and pre-processed Volatility output files, with incident response activities conducted using F-Response forensic acquisition tools.

The evidence inventory comprises memory dumps from three systems (the domain controller, nromanoff, and the XP workstation), disk images from all four systems, and pre-existing Volatility analysis output files generated during a prior examination. A total of 22 evidence sources were indexed across 614 forensic tool invocations, spanning Volatility 3 memory analysis, Sleuth Kit disk forensics, EZ Tools artifact parsing (MFT, ShimCache, Prefetch), YARA signature scanning, bulk_extractor IOC carving, Hayabusa and Chainsaw detection engines, and registry analysis via RegRipper.

The investigation produced 28 findings, of which 21 are corroborated by multiple independent evidence sources and 7 are assessed at inference-level confidence. No findings were ruled out as negative. The analysis identified activity mapping to 38 distinct MITRE ATT&CK techniques, reflecting a sophisticated, multi-phase intrusion that progressed from initial access through credential theft to classified data access.

## Incident Timeline

The incident unfolded across approximately four days, from April 3 through April 6, 2012, with the attacker demonstrating a structured operational tempo that moved through distinct phases of increasing impact.

**Phase 1 — Initial Payload Deployment (2012-04-03 18:08 UTC)**

The earliest confirmed malicious activity on the nromanoff workstation occurred at 18:08:50 on April 3, when three executables were deployed simultaneously: C:\dllhost.exe, C:\dllhot.exe (a misspelled variant), and an executable hidden in the Recycle Bin ($RR3GW21.exe). All three share the identical timestamp, indicating automated batch deployment. The placement of executables at the filesystem root and the deliberate misspelling of Windows binary names (dllhot vs. dllhost) are hallmarks of an attacker staging tools for later use while attempting to blend with legitimate system binaries.

**Phase 2 — Group Policy Weaponization (2012-04-03 20:38 UTC)**

At 20:38:07, MFT analysis reveals the simultaneous creation of new GroupPolicy\Machine\Scripts directories on both the nromanoff and nfury workstations. While domain-joined workstations normally synchronize Group Policy on periodic refresh cycles, the creation of entirely new Machine\Scripts directories — rather than mere modification of existing gpt.ini version counters — indicates a new Group Policy Object containing startup or logon scripts was deployed to the domain for the first time. This action requires domain administrator credentials, consistent with the attacker having already compromised the domain controller via webshell access.

**Phase 3 — Malware Staging via PsExec (2012-04-03 21:03–21:20 UTC)**

Beginning at 21:03:06, the Meterpreter stager TopLZAGU.exe (15,872 bytes, consistent with a standard Meterpreter payload size) was dropped into C:\Windows\ on the nromanoff workstation. Between 21:11 and 21:19, ShimCache recorded seven distinct PSEXESVC.EXE deployments on nromanoff, confirming that PsExec was used repeatedly from the domain controller to execute commands remotely. During this window, oSCMpGpk.exe was also executed at 21:18:14. The rapid-fire cadence of seven PsExec sessions within eight minutes is more consistent with automated attack scripting than manual administration.

**Phase 4 — Additional Tooling and Masquerading (2012-04-03 22:38–22:53 UTC)**

At 22:38:10, the vibranium user account downloaded winclient.exe and winclient.reg from the external IP 207.58.245.179 via Firefox. The .reg file likely configured registry-based persistence or C2 settings. At 22:40:25, a svchost.exe binary was placed inside a fabricated dllhost\ subdirectory within System32 — a process masquerading technique designed to evade casual inspection. The same dllhost\svchost.exe structure was later confirmed on the XP workstation, demonstrating cross-system coordinated deployment. Additionally, spinlock.exe was executed at 22:53 but crashed, generating a Windows Error Report.

**Phase 5 — C2 Beaconing and Credential Theft (2012-04-03 23:09 to 2012-04-04 01:47 UTC)**

Beginning at 23:54:46, a Python-packaged executable named a.exe began beaconing from C:\Windows\TEMP\ (SYSTEM context) at remarkably regular 65-second intervals. PyInstaller extraction artifacts containing python25.dll and _ctypes.pyd confirm the executable was built with Python 2.5 with Windows API access capabilities. At 01:00:45, hydrakatz.exe was executed from C:\windows\system32\ — a credential dumping tool whose name directly references the mimikatz family. Corroborating this, bulk_extractor carved a URL reference to blog.gentilkiwi.com (the official mimikatz distribution site) from the nromanoff disk image. A final PsExec session was recorded at 01:46:37, likely used to collect harvested credentials.

**Phase 6 — Sensitive Data Access (2012-04-04 15:42 UTC)**

MFT analysis confirmed that a document titled "Agents-List-CLASSIFIED-TOP-SECRET" was opened at 15:42:58 via the vibranium user account, as evidenced by the .lnk shortcut file created in the Recent Items folder. A second sensitive document, "Credit-Card-Numbers-For-Research.xls," was accessed at 15:42:01. While individual document access could represent legitimate user activity, the timing falls squarely within the confirmed compromise window and the vibranium account was actively used by the attacker for malware downloads from external infrastructure.

**Phase 7 — Lateral Movement to XP System (2012-04-04 17:06 UTC)**

By 17:06:37, the attack had extended to the XP workstation (10.3.58.7, user tdungan). ShimCache analysis confirmed spinlock.exe at position 0 (most recently cached program) and the identical dllhost\svchost.exe masquerading structure. Volatility netscan from the domain controller revealed a CLOSED SMB connection to 10.3.58.7 on port 445, matching the PsExec lateral movement pattern observed against nromanoff.

**Phase 8 — Persistent Rootkit and Ongoing Beaconing (through 2012-04-06 20:52 UTC)**

Pre-existing Volatility apihooks analysis from the nromanoff memory dump revealed inline JMP hooks in services.exe (PID 676) redirecting NtCreateThread and NtQueryDirectoryFile to unknown memory regions — classic Zeus/Zbot rootkit behavior providing thread injection and file-hiding capabilities. On the XP system, the rootkit was far more extensive: services.exe contained 22 hooked functions spanning credential interception (WININET HTTP hooks), keylogging (USER32 TranslateMessage), certificate theft (CRYPT32 PFXImportCertStore), and network interception (WS2_32 send/WSASend), while lsass.exe contained 4 additional hooks. These hooks were clearly distinguishable from legitimate McAfee HIPS hooks, which used IAT redirections to the known mfehidk.sys driver rather than inline JMPs to unmapped memory regions.

The a.exe C2 beacon continued operating through the final memory capture on April 6 at 20:52:56, now executing from the vibranium user's AppData\Local\Temp directory in addition to the SYSTEM-context Windows\TEMP path, indicating persistence across privilege levels. MFT confirmed the user-context variant was created at 13:43:21 on April 6 (9,216 bytes), demonstrating the attacker maintained active access for at least three days.

## Key Findings

**Webshell Arsenal on Domain Controller**

YARA scanning of the domain controller memory dump identified five distinct webshell and remote execution tool signatures active within the IIS worker process w3wp.exe (PID 152840): CmdAsp.asp (ASP-based command execution), cmdjsp.jsp (JSP-based command execution at three memory offsets), connectback2_pl (Perl reverse-connect backdoor), sql_php (PHP-based SQL injection tool referencing rst.void.ru), and RemCom (an open-source PsExec alternative). Volatility malfind corroborated these findings by detecting PAGE_EXECUTE_READWRITE memory regions in w3wp.exe. While RWX memory regions in .NET processes can result from legitimate JIT compilation, the convergence of malfind detections with five independent YARA webshell signature matches in the same IIS worker process makes code injection highly likely for w3wp.exe specifically. The co-occurrence of webshell families targeting four different web technologies (ASP, PHP, JSP, Perl) suggests either a comprehensive toolkit deployment or exploitation of multiple web application vulnerabilities on the server.

**Critical Architectural Vulnerability — IIS on Domain Controller**

The domain controller simultaneously served as the internet-facing web server for www.stark-research-labs.com, with SharePoint 2010 components installed and HTTP logs confirming sustained external access from numerous public IP addresses dating back to 2005. This configuration violates fundamental security architecture principles: any web server compromise immediately yields domain controller-level access, bypassing all network segmentation and privilege escalation requirements. Historical IIS logs also reveal directory traversal attack attempts dating to January 2005, indicating the server has been a target of opportunity for years.

**Zeus/Zbot Banking Trojan Deployment**

Two independent systems — the nromanoff workstation and the XP workstation — exhibited API hook patterns consistent with the Zeus/Zbot malware family. On nromanoff, services.exe contained inline JMP hooks on NtCreateThread and NtQueryDirectoryFile redirecting to unknown module addresses. On the XP system, the infection was substantially more developed, with 22 hooked functions in services.exe and 4 in lsass.exe, enabling credential interception, keylogging, certificate theft, network data interception, and rootkit-level file hiding. The identical hook technique (inline/trampoline JMPs to unmapped memory) and the same target functions across both systems provide strong cross-system corroboration. While the attribution to the Zeus/Zbot family specifically is partly informed by the naming of precooked analysis files, the hook patterns are consistent with published Zeus/Zbot technical analyses.

**Coordinated Anti-Forensics Campaign**

The attacker conducted systematic evidence destruction across at least three of the four analyzed systems. On the nromanoff workstation, both Security.evtx (3 KB) and System.evtx (8 KB) contained zero event records — only CSV headers remained. On the nfury workstation, the pattern was identical: Security.evtx occupied 128 MB on disk but contained zero records, and System.evtx (7.1 MB) was equally empty. The nfury system was also rebooted between the compromise window and the memory capture on April 6, clearing all volatile evidence; the memory dump shows only the Windows logon screen with no interactive user session. On the domain controller, the SysInternals toolkit directory contents (including PsExec.exe) were deleted, with TSK showing "realloc" status indicating disk space was reallocated. SDelete.exe was available in the toolkit, potentially enabling secure deletion. The identical pattern of empty event logs on two independent workstations strongly suggests a coordinated clearing action, likely executed via Group Policy script or PsExec sweep from the compromised domain controller.

**C2 Infrastructure and Persistent Access**

The investigation confirmed one external C2 IP address: 207.58.245.179 served as a malware download server, with bulk_extractor URL carving revealing that winclient.exe and winclient.reg were downloaded from this IP via the vibranium user's Firefox browser. The a.exe Python beacon provided a persistent C2 channel, executing every approximately 65 seconds from both SYSTEM and user contexts over a period of at least three days. A previously reported connection from lsass.exe to external IP 56.171.18.32 was investigated and assessed as a likely Volatility netscan artifact: the connection entry showed a dash instead of a valid local address, both ports at zero, CLOSED state with no creation timestamp, and no corroboration from any other evidence source. This IP should not be treated as confirmed C2 infrastructure.

## Threat Intelligence and Attribution

The intrusion exhibits characteristics consistent with a financially motivated or espionage-oriented threat actor possessing moderate to advanced capabilities. The operational profile includes several distinguishing features.

The deployment of five distinct webshell families targeting four web technologies (ASP, PHP, JSP, Perl) alongside the RemCom remote execution framework indicates access to a comprehensive offensive toolkit rather than a single exploit. The use of Zeus/Zbot — a banking trojan widely available in underground markets during this period — as a persistence and credential interception mechanism is notable. Zeus source code was publicly leaked in 2011, enabling widespread adoption by diverse threat groups, which limits its attribution value to any single actor. However, the combination of Zeus with Meterpreter (TopLZAGU.exe), mimikatz-family tools (hydrakatz.exe), and custom Python C2 beacons (a.exe) demonstrates a willingness to combine commodity and custom tooling.

The attacker's operational tradecraft — including process masquerading (svchost.exe in fabricated dllhost directories), Group Policy abuse for malware distribution, systematic log clearing across multiple systems, and the use of legitimate administrative tools (PsExec) alongside dedicated attack tools (RemCom) — reflects operational maturity. The coordinated deployment of identical malware (spinlock.exe, dllhost\svchost.exe) across multiple workstations and the progression from web server compromise to domain-level credential theft to classified data access indicates a structured objective rather than opportunistic exploitation.

Definitive attribution to a specific threat group cannot be established from the available evidence. The tooling overlaps with TTPs used by multiple threat actors active during this period. The presence of webshells commonly distributed through offensive security communities (CmdAsp from dogmile.com, cmdjsp from michaeldaw.org, sql_php from rst.void.ru) is consistent with publicly available penetration testing resources rather than custom-developed implants. The investigation can confirm the operational sophistication and objective (access to classified personnel data) but cannot conclusively identify the responsible party.

## Impact Assessment

The compromise affected all four analyzed systems within the Stark Research Labs domain, representing a complete domain-level breach. The domain controller — the highest-value target in any Active Directory environment — was compromised with SYSTEM-level webshell access, providing the attacker with unrestricted control over all domain resources, user accounts, Group Policy, and authentication mechanisms.

Three workstations were confirmed compromised with varying degrees of persistence: nromanoff (Meterpreter, Zeus rootkit, C2 beacon, credential theft tools), the XP workstation (Zeus rootkit with extensive API hooks, matching malware), and nfury (Group Policy modified, event logs cleared, though no persistent malware was recovered from disk or memory). The NTDS.dit Active Directory database was accessible to the attacker, meaning all domain user password hashes should be considered compromised.

Sensitive data confirmed accessed during the compromise window includes a document titled "Agents-List-CLASSIFIED-TOP-SECRET" and "Credit-Card-Numbers-For-Research.xls." Additional financial documents including "CC-Backstopped-Accounts.xlsx" were present on compromised systems. On the XP workstation, Dropbox was installed and actively used, providing a potential cloud-based exfiltration vector, while Zeus WININET hooks were positioned to intercept all HTTP traffic including cloud storage sessions.

Multiple exfiltration channels were available to the attacker: the a.exe Python C2 beacon (active for at least three days), winclient.exe (downloaded from the attacker's infrastructure), Zeus HTTP interception capabilities, and potentially Dropbox. While no direct evidence of data exfiltration volume was recovered — the systematic anti-forensics campaign including log clearing and system reboots may have destroyed such evidence — the confirmed access to classified documents during an active compromise window creates a reasonable assumption that data was accessed with intent to exfiltrate.

## Immediate Tactical Containment

1. Isolate all four compromised systems from the network immediately: domain controller (10.3.58.4 / 10.3.58.9), nromanoff (10.3.58.5), nfury (10.3.58.6), and the XP workstation (10.3.58.7). Block at the switch port level — do not rely on host-based firewalls, as the Zeus rootkit can intercept network calls.

2. Block external IP 207.58.245.179 (confirmed malware download server) at the perimeter firewall in both directions. Add to all proxy, DNS sinkhole, and IDS blocklists.

3. On the nromanoff workstation, terminate the a.exe C2 beacon process executing from C:\Windows\TEMP\a.exe (SYSTEM context) and C:\Users\vibranium\AppData\Local\Temp\a.exe (user context). This beacon contacts external C2 infrastructure every 65 seconds.

4. Disable the vibranium domain user account immediately — this account was used to download malware from attacker infrastructure and access classified documents during the active compromise.

5. Disable the tdungan domain user account — the XP workstation under this account has active Zeus rootkit hooks intercepting all HTTP credentials and certificate operations.

6. Force a domain-wide password reset for ALL accounts, prioritizing domain administrators, service accounts, and the nfury, nromanoff, and tdungan user accounts. The attacker had SYSTEM access on the domain controller and executed credential theft tools (hydrakatz.exe).

7. Take the IIS web server (www.stark-research-labs.com) offline immediately by stopping the World Wide Web Publishing Service on the domain controller. The w3wp.exe process (PID 152840) hosts active webshells providing SYSTEM-level command execution.

8. Block the following file hashes and filenames at endpoint protection systems: TopLZAGU.exe, hydrakatz.exe, a.exe (9,216 bytes), spinlock.exe, winclient.exe, dllhost.exe (at C:\ root), dllhot.exe, oSCMpGpk.exe, and any svchost.exe located within a dllhost\ subdirectory.

9. Revoke all Kerberos tickets (krbtgt account double-reset) to invalidate any Golden Tickets the attacker may have created with domain controller SYSTEM access.

10. Quarantine the SysInternals toolkit directory C:\Tools\SysInternals\ on the domain controller and audit any remaining PsExec service artifacts (PSEXESVC.EXE) across all domain workstations.

## Strategic Remediation

The root cause of this breach was the deployment of an internet-facing IIS web server directly on the domain controller, which collapsed the organization's entire trust boundary into a single attack surface. The webshells discovered in the w3wp.exe process (CmdAsp.asp, cmdjsp.jsp, connectback2_pl, sql_php, and RemCom) confirm that web application vulnerabilities provided the initial access vector, and because IIS ran on the domain controller with SYSTEM privileges, this single compromise immediately yielded domain administrator-equivalent access. Stark Research Labs must separate web-facing services from domain controller infrastructure onto dedicated, hardened web servers in a DMZ segment, with no direct Active Directory role colocation.

The attacker's ability to weaponize Group Policy for malware distribution across workstations — confirmed by the synchronized creation of GroupPolicy\Machine\Scripts directories on nromanoff and nfury at 20:38:07 on April 3, followed by TopLZAGU.exe deployment 25 minutes later — demonstrates that no monitoring or change detection existed for Group Policy modifications. Implementing real-time alerting on GPO creation and modification, with mandatory approval workflows for any Group Policy containing script execution, would have detected this lateral movement technique before payloads reached workstations.

The seven PsExec sessions from the domain controller to the nromanoff workstation between 21:11 and 21:19 on April 3 — confirmed by PSEXESVC.EXE shimcache entries — occurred without generating any security alerts, indicating that neither the domain controller nor the workstation had adequate monitoring for remote service installation or lateral movement via administrative shares. Deploying endpoint detection and response capabilities with specific rules for PSEXESVC.EXE deployment, remote service creation (Event ID 7045), and anomalous SMB traffic patterns from domain controllers would provide detection coverage for this confirmed attack vector.

The complete clearing of Windows Security and System event logs on both nromanoff and nfury — with Security.evtx reduced to zero records despite occupying 128 MB on disk on nfury — succeeded because no centralized log forwarding existed. Had event logs been forwarded in real time to a Security Information and Event Management system, the log clearing events themselves (Event ID 1102) would have generated alerts, and the authentication and service installation events preceding the clearing would have been preserved for analysis. The absence of log forwarding directly enabled the anti-forensics campaign documented in this investigation.

The execution of hydrakatz.exe from C:\windows\system32\ at 01:00:45 on April 4 and the sustained a.exe C2 beaconing every 65 seconds from C:\Windows\TEMP\ demonstrate that the McAfee VirusScan Enterprise deployment (confirmed active on all systems) failed to detect or block known credential theft tools and anomalous beaconing behavior. Application whitelisting or enhanced endpoint protection with behavioral detection capabilities — specifically monitoring for execution of unknown binaries from TEMP directories, single-character executable names, and regular-interval outbound connections — would have disrupted both the credential theft and C2 phases of this attack.

The attacker's confirmed access to "Agents-List-CLASSIFIED-TOP-SECRET" and "Credit-Card-Numbers-For-Research.xls" on the nromanoff workstation, combined with the absence of any data loss prevention controls, means the organization has no visibility into whether these documents were exfiltrated. Implementing data classification enforcement and monitoring for bulk file access, unusual file copy operations, and transfers to cloud storage services (Dropbox was installed on the XP workstation) would provide both prevention and audit trail capabilities for sensitive data access during future incidents.

## Conclusion

**Q1. What systems were compromised?**

All four analyzed systems were compromised. The domain controller (10.3.58.4) hosted five active webshell families and the RemCom remote execution tool in memory. The nromanoff workstation (10.3.58.5) was infected with Meterpreter, Zeus/Zbot rootkit hooks, the a.exe C2 beacon, credential theft tools (hydrakatz.exe), and multiple masquerading executables. The XP workstation (10.3.58.7) contained an extensive Zeus/Zbot rootkit with 26 API hooks across services.exe and lsass.exe, plus matching malware (spinlock.exe, dllhost\svchost.exe). The nfury workstation (10.3.58.6) had its Group Policy modified and event logs cleared as part of the coordinated attack, though no persistent malware was recovered from its memory or disk at the time of capture — likely due to a system reboot between the compromise and evidence collection.

**Q2. How did the attacker gain initial access?**

The attacker gained initial access through the exploitation of the internet-facing IIS web server running on the domain controller hosting www.stark-research-labs.com. Five webshell families detected in the w3wp.exe process memory confirm web application compromise as the initial access vector. The critical architectural decision to colocate an internet-facing web server with the domain controller meant this single compromise immediately provided SYSTEM-level access to the domain's most privileged system.

**Q3. What lateral movement occurred?**

Lateral movement was conducted primarily via PsExec from the domain controller to internal workstations. Seven PSEXESVC.EXE deployments were recorded on the nromanoff workstation between 21:11 and 21:19 on April 3, with an eighth session at 01:46 on April 4. SMB connections from the domain controller to both the nromanoff workstation (ESTABLISHED at time of memory capture) and the XP workstation (CLOSED) confirm SMB-based lateral movement to at least two endpoints. Group Policy modification was used as a secondary distribution mechanism, with new Machine\Scripts directories created simultaneously on nromanoff and nfury.

**Q4. What persistence mechanisms were installed?**

Multiple persistence mechanisms were deployed across the compromised environment. Zeus/Zbot rootkit API hooks in services.exe and lsass.exe on two workstations provided process-level persistence with file-hiding capabilities. The a.exe Python C2 beacon operated from both SYSTEM and user contexts, executing every 65 seconds for at least three days. Group Policy modification created new script execution directories that could survive system reboots. Process masquerading (svchost.exe within fabricated dllhost directories) was deployed on two systems for long-term evasion. The winclient.reg file downloaded from attacker infrastructure likely configured additional registry-based persistence.

**Q5. Was data exfiltrated, and if so, what and how much?**

Confirmed access to "Agents-List-CLASSIFIED-TOP-SECRET" and "Credit-Card-Numbers-For-Research.xls" was documented on the nromanoff workstation during the active compromise window. The precise volume of exfiltrated data cannot be determined due to the attacker's systematic anti-forensics campaign (log clearing, system reboots). However, multiple exfiltration channels were available and active: the a.exe C2 beacon (beaconing every 65 seconds for three or more days), winclient.exe (C2 implant downloaded from 207.58.245.179), Zeus WININET hooks intercepting all HTTP traffic on the XP system, and Dropbox installed on the XP workstation. Given the attacker's confirmed access to classified documents, sustained C2 connectivity, and credential theft capabilities, data exfiltration should be assumed to have occurred.

**Q6. What is the full timeline of the incident?**

The active attack phase spanned from April 3 at 18:08 UTC (initial payload deployment on nromanoff) through at least April 6 at 20:52 UTC (final confirmed a.exe beaconing at time of memory capture). The initial compromise of the domain controller via webshells likely predates April 3, as the attacker already possessed the domain-level privileges necessary to deploy Group Policy modifications and conduct PsExec lateral movement at the start of the observed activity. The seven key operational phases are detailed in the Incident Timeline section above.

**Q7. What is the total scope and business impact?**

The compromise represents a complete domain-level breach affecting all analyzed systems in the Stark Research Labs infrastructure. The attacker achieved the highest possible level of access — SYSTEM privileges on the domain controller — and leveraged this to distribute malware and clear evidence across the domain. Classified personnel data ("Agents-List-CLASSIFIED-TOP-SECRET") and financial records were accessed during the compromise. All domain credentials should be considered compromised given the attacker's SYSTEM access to the domain controller (and thus NTDS.dit) and confirmed execution of credential theft tools. The business impact includes potential exposure of classified personnel information, financial data, and all domain user credentials, with the added risk that the attacker maintained persistent access for multiple days with active C2 channels.

**Q8. What are the recommended remediation actions?**

Immediate tactical containment steps are detailed in the Immediate Tactical Containment section. Strategic remediation requires separating internet-facing web services from domain controller infrastructure, implementing centralized log forwarding to prevent anti-forensics success, deploying Group Policy change monitoring and approval workflows, enhancing endpoint detection capabilities to identify credential theft tools and C2 beaconing behavior, and implementing data loss prevention controls for classified and sensitive documents. A domain-wide credential reset including double-rotation of the krbtgt account is essential to invalidate any persisted authentication material.
