## Investigation Report

# Stark Research Labs Network Intrusion and Industrial Espionage Investigation

## Background

This investigation examines evidence of a network intrusion and data theft operation targeting Stark Research Labs (SRL), a materials research organization operating under the domain SHIELDBASE.LAN during August–September 2018. The organization conducts research into rare-earth elements and maintains corporate intellectual property related to mergers and acquisitions strategy for mining companies. The case identifier is SRL-2018.

The evidence corpus consists of 23 indexed forensic sources spanning nine distinct extractor categories: memory forensics (Volatility 3), disk imaging (The Sleuth Kit), event log analysis (EVTX), registry parsing (RegRipper and EZ Tools), data carving (bulk_extractor), YARA signature scanning, and detection rule engines (Hayabusa and Chainsaw). Memory dumps were obtained from at least six systems, and disk images were acquired from five systems. A total of 1060 forensic tool invocations were executed during this investigation.

The environment is built on VMware virtual infrastructure running the SHIELDBASE.LAN Active Directory domain (SID S-1-5-21-3445421715-2530590580-3149308974). Key systems include BASE-DC (Domain Controller, Windows Server 2016, 172.16.4.4), BASE-FILE (file server, 172.16.4.5), BASE-MAIL (mail server, 172.16.4.6), base-rd-01 (R&D workstation, 172.16.6.11), base-rd-02 (Java application server, 172.16.6.12), base-wkstn-01 (Terminal Services/RDS server, 172.16.7.11), base-wkstn-05 (user workstation), and a DMZ FTP server (172.16.10.12). Security software consisted of dual concurrent antivirus deployments — McAfee VirusScan Enterprise with Host Intrusion Prevention, and Windows Defender — managed centrally via McAfee ePO at 172.16.4.10:8080. Configuration management was handled by Puppet across several systems.

An incident response team was demonstrably active before the confirmed attack window: Autorunsc was executed on 2018-08-15, and Plaso forensic acquisition was running on base-wkstn-01 since 2018-08-29. F-Response Subject agents were deployed across the environment on 2018-09-06 for remote forensic evidence access, coordinated from the base-hunt forensic workstation (172.16.5.25/26). The Mnemosyne memory acquisition driver was loaded on the Domain Controller for memory capture. These forensic artifacts were confirmed as legitimate investigation tools and are not indicators of compromise.

## Incident Timeline

The investigation identified two concurrent threat vectors operating within the same timeframe, organized into the following operational phases.

**Phase 1 — Pre-Compromise Indicators and Possible Early Persistence (August 2018 and Earlier)**

The earliest anomalous artifact is the presence of two masquerading service binaries on base-rd-02: msadvapi2_64.exe (PID 2328) and msadvapi2_32.exe (PID 2292), both running as Windows services under services.exe since system boot on 2018-08-19 06:23:13. These binaries adopt naming conventions mimicking Microsoft's advapi32.dll, a known defense evasion technique. Their dual-architecture deployment (both 32-bit and 64-bit variants) and presence exclusively on base-rd-02 — no other system in the environment runs these binaries — is noteworthy. However, binary analysis was not performed, and it remains possible that these represent a legitimate but obscure monitoring agent deployed via Puppet. This finding carries an inference confidence level pending further binary analysis.

**Phase 2 — WMI-Based Lateral Movement and Initial Payload Deployment (August 30, 2018)**

The confirmed attack commenced on 2018-08-30 at 16:43:36 UTC when WmiPrvSE.exe (PID 2876) on base-rd-01 spawned powershell.exe (PID 8712) in Session 0, indicating WMI-based remote code execution. Within six seconds, a 32-bit PowerShell child process (PID 5848, Wow64=True) was launched with the flags -NoLogo -NoProfile, reducing the logging footprint. At 22:15:18 UTC, cmd.exe (PID 5948) executed the primary malware payload: c:\windows\temp\perfmon\p.exe (PID 8260). Volatility malfind analysis revealed that p.exe allocated 481 pages of PAGE_EXECUTE_READWRITE memory, a massively anomalous RWX allocation far exceeding any legitimate application, strongly indicating a packed or encrypted in-memory payload consistent with a remote access tool.

Beginning at 18:31:04 UTC on the same day, the 32-bit PowerShell process and later p.exe itself began spawning short-lived rundll32.exe proxy execution processes. Nine such instances were observed over the following seven days, from 2018-08-30 through 2018-09-06, indicating persistent command-and-control capability with periodic task execution.

**Phase 3 — Environment-Wide Propagation (August 31, 2018)**

Approximately eight and a half hours after the initial compromise of base-rd-01, the same WMI attack chain was replicated on base-wkstn-01 and base-av. On base-wkstn-01, WmiPrvSE.exe (PID 2676, started 2018-08-30 05:14:54) spawned multiple PowerShell processes beginning at 2018-08-31 01:14:44 UTC, each following the identical chain: 64-bit PowerShell to 32-bit PowerShell (Wow64) to rundll32.exe. A persistent rundll32.exe instance (PID 7100, 5 threads, 337 handles) was established at 18:43:50 UTC and remained active at the time of memory acquisition, demonstrating sustained attacker presence. The base-av system exhibited an identical chain originating from WmiPrvSE.exe (PID 2676) through PowerShell (PID 3920) to a 32-bit child (PID 1332) at 01:31:25 UTC, with its own persistent rundll32.exe (PID 7100). The use of WMI remote execution across these systems requires valid domain administrative credentials, establishing that the attacker had already obtained such access prior to this propagation phase.

Also on 2018-08-31, at 20:23:20 UTC, the attacker staged confidential R&D data on the Domain Controller. The MFT reveals a file at Windows\Temp\perfmon\research\Rare-Earth Elements\M&A Targets\Orocobre\2018 Results\ORE_Investor-Presentation_July-2018_Final.pdf (1.9 MB), organized within a structured directory hierarchy indicating deliberate categorization of stolen intellectual property. The perfmon staging directory naming convention matches the malware deployment path on base-rd-01, linking this data staging to the same threat actor.

At 23:28:16 UTC, ShimCache evidence from base-rd-01 records access to \\172.16.4.6\c$\Windows\Logs\WindowsServerBackup\6.14\volrest.exe via the BASE-MAIL administrative share, indicating the attacker staged additional tools on the mail server and accessed them remotely.

**Phase 4 — DMZ FTP Server Reconnaissance and Compromise (August–September 2018)**

Running concurrently with the internal WMI campaign, a separate attack vector targeted the DMZ FTP server at 172.16.10.12. External brute force attempts began on 2018-08-08 from multiple global IP addresses, including 124.65.64.174 and 60.212.42.56, targeting usernames "stark-r" and "administrator." These initial attempts failed with 530 authentication errors. On 2018-09-02, anonymous FTP access by 149.202.71.206 and 94.23.20.187 successfully enumerated the /Users directory structure, exposing account names including nfury and rsydow-f. On 2018-09-03, the external IP 165.227.50.129 attempted to authenticate as nfury (failed), navigated the rsydow-f directory, and downloaded test.txt. By 2018-09-05, 165.227.50.129 successfully authenticated as DMZ-FTP\rsydow-f and conducted multiple data transfer operations between 16:37 and 18:48 UTC. Additionally, 35.205.86.202 conducted extensive directory enumeration using LIST -a (hidden file listing) across multiple sessions from August 20 through September 3.

On 2018-09-04 at 17:37–17:38, an Nmap NSE scan was detected from the internal DMZ host 172.16.10.13 targeting the FTP server on ports 80 and 443. While this could represent an authorized security scanner, its timing between the external reconnaissance phase and authenticated access phase warrants attention. WebDAV OPTIONS requests from 172.16.5.26 (the IR workstation) probing /c$ and /srl-ftp on 2018-09-07 are assessed as likely incident response investigation activity.

**Phase 5 — Continued Internal Operations and Credential Harvesting (September 3–6, 2018)**

On 2018-09-05 at 12:01:32, p.exe (PID 8260) spawned another rundll32.exe instance (PID 5768) on base-rd-01, demonstrating continued C2 activity. At 12:17:02, the SECURITY registry hive was copied to \temp\registry\SECURITY on the Domain Controller (MFT entry 132834, 65536 bytes). While the IR team was active at this time and forensic analysts may perform similar hive collection, the non-standard path, the selective extraction of only the SECURITY hive, and the convergent attack activity on the same day favor an attacker-driven credential harvesting interpretation — though this assessment carries inference-level confidence.

At 14:05:51 UTC, ShimCache records the access of ri.exe from \\172.16.4.6\c$\Windows\Temp\perfmon\ via administrative shares on BASE-MAIL, confirming continued tool staging in the attacker's perfmon directory convention across yet another system.

On 2018-09-06, the attack chain reached base-rd-02 when WmiPrvSE.exe (PID 3924) spawned a 32-bit PowerShell process (PID 6528) at 17:10:53 UTC, accompanied by extensive reconnaissance using sc.exe and netstat.exe. This represents the latest confirmed system compromise in the attack timeline.

**Phase 6 — Forensic Response and Evidence Collection (September 6–7, 2018)**

On 2018-09-06, the incident response team deployed F-Response Subject agents across the environment: base-rd-01 (PID 1096, 18:28:30), base-rd-02 (PID 1204, 19:03:45), and BASE-DC (PID 5128, 22:11:15), all reporting to the F-Response server at base-hunt.shieldbase.lan:5682. Memory dumps were acquired using the Mnemosyne driver. The Domain Controller was shut down on 2018-09-07 at 20:25:33 UTC. Forensic response tools, including fresponse-agent.msi and the Mnemosyne.sys driver, were staged on the FTP server's root directory.

## Key Findings

The investigation produced 50 findings, of which 4 are rated critical severity, 9 high, 7 medium, and 5 low. A total of 42 findings carry confirmed confidence, corroborated by two or more independent evidence sources, while 8 carry inference-level confidence. The findings map to 30 distinct MITRE ATT&CK techniques.

**Malware and Attack Tooling**

The primary malware artifact is p.exe, deployed to c:\windows\temp\perfmon\p.exe on base-rd-01 and executed via the WMI-initiated command chain (WmiPrvSE.exe → powershell.exe → powershell.exe 32-bit → cmd.exe → p.exe). Volatility malfind analysis detected 481 pages of PAGE_EXECUTE_READWRITE memory in this process — an allocation orders of magnitude beyond legitimate software — indicating a packed or encrypted in-memory payload. The binary loaded standard Windows APIs (ADVAPI32.dll, sechost.dll, RPCRT4.dll) for service and registry interaction, and maintained active execution from its deployment on 2018-08-30 through the memory capture on 2018-09-06, spawning nine rundll32.exe proxy execution instances over that period.

Two additional attacker tools were identified through ShimCache analysis: ri.exe, staged at \\172.16.4.6\c$\Windows\Temp\perfmon\ on BASE-MAIL, and volrest.exe, staged at \\172.16.4.6\c$\Windows\Logs\WindowsServerBackup\6.14\ on the same server. Both were accessed via administrative shares from base-rd-01, confirming the attacker possessed domain-level administrative credentials and used BASE-MAIL as a tool staging server. Binary analysis was not performed on any of these tools as the evidence was derived from memory dumps and registry artifacts rather than extracted executables.

On base-rd-02, two suspicious service binaries — msadvapi2_64.exe (PID 2328) and msadvapi2_32.exe (PID 2292) — ran as Windows services from boot time (2018-08-19 06:23:13). Their naming convention masquerades as Microsoft's advapi32.dll, and they are unique to base-rd-02 within the environment. While these could represent an obscure legitimate management agent, their naming pattern and single-system presence maintain a high-severity inference assessment pending binary analysis.

YARA scanning across all systems produced no confirmed malware signature matches. The APT6_Malware_Sample_Gen rule matched generic Windows strings (system paths, networking terms, copyright notices) across all memory dumps, confirmed as false positives through string-level analysis. Similarly, APT_MAL_RU_WIN_Snake_Malware_May23_1 matched common format specifiers and file extensions on disk images, with no evidence of Snake/Turla malware presence.

**Lateral Movement and Persistence**

The WMI-based remote code execution chain was deployed across at least four systems (base-rd-01, base-wkstn-01, base-av, and base-rd-02) using an identical technique sequence. The attack leveraged valid domain administrative credentials for WMI invocation and administrative share access (C$). PowerShell processes were launched with -NoLogo -NoProfile flags to minimize logging, and 32-bit (Wow64) PowerShell variants were used as an intermediate stage before spawning rundll32.exe for fileless payload execution. On base-wkstn-01 and base-av, persistent rundll32.exe processes (PID 7100 on both, with 5 threads and 337 handles) remained active at memory capture time, demonstrating sustained attacker access.

Network analysis confirmed cross-system SMB connections, including an established connection from base-rd-01 (172.16.6.11:59352) to 172.16.7.15:445, providing evidence of lateral movement or file share access involving the compromised R&D workstation. WinRM connections (port 5985) were observed between multiple systems, though some represent legitimate administrative and forensic tool activity from the IR workstation.

On the file-less attack methodology: despite the confirmed WMI attack chain in memory on base-wkstn-01, a thorough search of its disk image found no persistent malware binaries, staging directories, or attacker artifacts on disk. This confirms the attacker employed a fileless attack approach using living-off-the-land binaries (WMI, PowerShell, rundll32.exe) that left no disk footprint, executing entirely in memory.

No kernel-level rootkits were detected. The modscan versus modules comparison across all four analyzed systems found no hidden kernel modules, ruling out kernel-level persistence.

**Data Theft and Exfiltration Staging**

The attacker targeted Stark Research Labs' core intellectual property — rare-earth elements research and M&A strategy. On the Domain Controller, the perfmon staging directory contained a structured hierarchy (perfmon\research\Rare-Earth Elements\M&A Targets\Orocobre\2018 Results\) with a 1.9 MB investor presentation from a real lithium mining company, created 2018-08-31 20:23:20, one day after p.exe was deployed. The file server (BASE-FILE) hosted additional sensitive materials including CONFIDENTIAL - Project Mayhem.pptx (1.7 MB) under the R&D shared directory.

Browser search history from base-rd-01 revealed systematic research data hunting with queries such as "carbon alloy research filetype:pdf/docx/pptx" and "carbonadium filetype:pdf," confirming targeted collection of materials research documents. The convergence of the perfmon staging directory across the malware deployment (base-rd-01), tool staging (BASE-MAIL), and data staging (DC) links all three activities to a single coordinated operation.

Whether the staged data was successfully exfiltrated from the network could not be conclusively determined from available evidence. The staging of data on the Domain Controller's perfmon directory indicates the attacker collected and organized the intellectual property, but no outbound data transfer to an external destination was directly observed in the analyzed artifacts.

**DMZ FTP Server Compromise**

The DMZ FTP server experienced a progressive multi-phase compromise, beginning with external scanning and brute force attempts from diverse global IP addresses (60.212.42.56, 124.65.64.174, 121.66.21.187, and others) targeting usernames aligned with the organization. Anonymous FTP access was enabled, allowing external parties to enumerate the directory structure and discover user account names. IP 165.227.50.129 escalated from anonymous enumeration (2018-09-03) to authenticated access as DMZ-FTP\rsydow-f (2018-09-05), conducting data transfers over a two-hour window. Forensic response tools were subsequently staged on the FTP server, creating the additional concern that the attacker's demonstrated file download capability could expose IR tool signatures.

## Threat Intelligence and Attribution

The investigation identified 30 distinct MITRE ATT&CK techniques employed across the attack, spanning Initial Access (T1078 Valid Accounts), Execution (T1047 WMI, T1059.001 PowerShell), Persistence (T1543.003 Windows Service), Defense Evasion (T1036.005 Masquerading, T1218.011 Rundll32, T1027.011 Fileless Storage), Credential Access (T1003 OS Credential Dumping, T1110 Brute Force), Discovery (T1046, T1057, T1083), Lateral Movement (T1021 Remote Services, T1570 Lateral Tool Transfer), Collection (T1005, T1039, T1074 Data Staging), and Impact staging.

The attack methodology demonstrates characteristics consistent with a well-resourced threat actor engaged in industrial espionage. The use of WMI for remote code execution, fileless PowerShell payloads, rundll32 proxy execution, and LOLBIN-based persistence reflects a mature operational tradecraft designed to evade signature-based detection — as evidenced by the zero alerts from Hayabusa, Chainsaw, and Sigma detection engines across all analyzed EVTX logs. The systematic targeting of rare-earth elements research and M&A intelligence suggests an adversary with specific interest in the organization's materials science and corporate strategy.

The dual-architecture deployment of msadvapi2 binaries on base-rd-02, while inconclusive, could indicate either a separate pre-existing compromise or a more established persistence mechanism from the same actor. The 11-day gap between the msadvapi2 installation (2018-08-19) and the WMI campaign onset (2018-08-30) leaves the relationship between these indicators unresolved.

The relationship between the internal WMI campaign and the external FTP compromise remains unclear. The internal compromise began before the FTP exploitation timeline (August 30 vs. September 2), suggesting these may represent independent attack vectors, or the FTP access may have served as a secondary objective or alternate persistence channel. No specific threat group attribution can be made based on the available evidence. YARA detections for APT6 and Snake/Turla malware signatures were thoroughly analyzed and confirmed as false positives caused by generic string matching against common Windows artifacts.

## Impact Assessment

The compromise affected a minimum of four confirmed systems (base-rd-01, base-wkstn-01, base-av, and base-rd-02) via the WMI attack chain, with strong evidence of tool staging on two additional systems (BASE-MAIL and BASE-DC). The DMZ FTP server experienced a separate but concurrent compromise. In total, at least seven systems across multiple network segments were directly affected.

The attacker obtained domain administrative credentials, most likely the rsydow-a account, enabling unrestricted lateral movement via administrative shares (C$), WMI remote execution, and potentially RDP. This level of credential compromise grants access to all domain-joined systems, the Active Directory database, and all network-accessible file shares.

Confirmed intellectual property exposure includes the staging of a 1.9 MB rare-earth elements M&A investor presentation on the Domain Controller. The file server hosts additional sensitive R&D data (CONFIDENTIAL - Project Mayhem.pptx, 1.7 MB) and management prospect analyses that were accessible to the compromised domain administrator account. Browser search history confirms the attacker systematically hunted for research documents using targeted filetype searches, indicating broader data collection likely occurred beyond what was captured in the MFT staging evidence.

The SECURITY registry hive extraction on the Domain Controller (2018-09-05 12:17:02) potentially exposed cached domain credentials, LSA secrets, and the SAM encryption key, amplifying the credential compromise beyond the initially obtained administrative account.

The persistence depth encompasses at minimum in-memory implants (p.exe with 481-page RWX allocation), persistent rundll32 processes across multiple systems, and potentially the msadvapi2 service binaries on base-rd-02. The attacker maintained sustained access from 2018-08-30 through at least 2018-09-06 — a minimum seven-day dwell time during which they had largely unfettered access to the organization's intellectual property and infrastructure.

## Strategic Remediation

The WMI-based attack chain (T1047) succeeded because Windows Management Instrumentation remote execution was enabled by default across the environment with no restrictions on which accounts or source systems could invoke remote WMI commands. This attack path was the attacker's primary lateral movement mechanism across all four confirmed compromised systems. Restricting WMI remote access via Windows Firewall rules, Group Policy, or DCOM configuration to limit which accounts and source IPs can execute remote WMI commands would have prevented the environment-wide propagation observed in this case.

The attacker operated with domain administrative credentials (rsydow-a) throughout the campaign, accessing C$ administrative shares across BASE-MAIL, base-rd-01, and the Domain Controller. The SECURITY hive extraction on the DC (finding f_a015a6f7) and the unrestricted administrative share access (finding f_a6780b9f) demonstrate that no privileged access controls limited the blast radius of a single compromised admin account. Implementing tiered administration — separating workstation admin, server admin, and domain admin credentials — with Privileged Access Workstations (PAWs) for domain administration would have constrained the attacker's ability to move from R&D workstations to domain controllers using a single credential set.

The fileless attack chain (PowerShell with -NoLogo -NoProfile flags, rundll32 proxy execution) evaded the dual McAfee VirusScan and Windows Defender deployments on every compromised system (finding f_07bc3a86, f_96b5f018, f_6884e9b4). Both antivirus products are signature-based and failed to detect the in-memory payload. The zero alerts from Hayabusa, Chainsaw, and Sigma rule engines across all EVTX logs (finding f_878f170c, f_fd30bd86) indicate that PowerShell ScriptBlock logging (Event ID 4104) and WMI activity tracing were either not enabled or not retained in sufficient volume. Deploying an EDR solution with behavioral detection for in-memory execution, combined with mandatory PowerShell ScriptBlock logging and WMI event subscription monitoring, would have provided detection capability for this attack methodology. The post-incident deployment of Sysmon and Velociraptor observed in the 2021 memory capture of base-wkstn-01 (finding f_0ab2fc8d) confirms that this remediation was subsequently undertaken.

The DMZ FTP server allowed anonymous access, enabling external parties to enumerate user account names in the /Users directory (finding f_c2ef8746). These enumerated usernames (nfury, rsydow-f) were subsequently used in targeted authentication attempts, with 165.227.50.129 eventually succeeding as rsydow-f. The FTP server also exposed forensic response tools in its root directory (finding f_63eaaa99). Disabling anonymous FTP access and removing the server from public exposure — or replacing it with SFTP with key-based authentication — would have prevented the account enumeration that enabled the credential-based compromise.

The attacker successfully staged 1.9 MB of R&D intellectual property on the Domain Controller (finding f_9fa4aae4) with no evidence that data loss prevention controls detected or blocked the movement of files marked CONFIDENTIAL. The organization's core rare-earth elements M&A research was copied to an attacker-controlled staging directory on the most privileged server in the network. Implementing DLP monitoring on domain controllers and file servers for sensitive document access patterns — particularly bulk reads or copies of files from R&D shares to non-standard directories like Windows\Temp — would provide visibility into this data staging activity.

## Conclusion

**Q1. What systems were compromised?** At least four systems were confirmed compromised via the WMI attack chain: base-rd-01 (172.16.6.11), base-wkstn-01 (172.16.7.11), base-av, and base-rd-02 (172.16.6.12). BASE-MAIL (172.16.4.6) was used as a tool staging server via administrative shares, and the Domain Controller (BASE-DC, 172.16.4.4) was used for data staging and credential harvesting. The DMZ FTP server (172.16.10.12) experienced a separate external compromise. base-wkstn-05 showed no direct compromise indicators on disk, though the absence of a memory dump limits this assessment.

**Q2. How did the attacker gain initial access?** The initial access vector for the internal network compromise could not be conclusively determined from available evidence. The attacker possessed domain administrative credentials (likely rsydow-a) when the WMI campaign began on 2018-08-30, but the method by which these credentials were originally obtained is not captured in the evidence. The msadvapi2 binaries on base-rd-02, active since 2018-08-19, may represent an earlier access vector. The DMZ FTP server was compromised via credential-based authentication after anonymous enumeration exposed account names, but whether this FTP compromise facilitated or was independent of the internal network compromise remains unresolved.

**Q3. What lateral movement occurred?** The attacker used WMI remote execution (T1047) as the primary lateral movement mechanism, deploying identical attack chains across four systems within a 7-day window. Administrative shares (C$) on BASE-MAIL were used for remote tool staging and execution. SMB connections between compromised systems and network scan evidence confirm cross-subnet movement.

**Q4. What persistence mechanisms were installed?** Persistence was achieved through in-memory implants (p.exe with 481-page RWX allocation on base-rd-01), persistent rundll32.exe processes (PID 7100 on base-wkstn-01 and base-av, running with 5 threads and 337 handles at capture time), and possibly the msadvapi2 Windows service binaries on base-rd-02 (running since boot). No registry-based autorun persistence or scheduled tasks were identified. The attack methodology favored fileless, memory-resident persistence over disk-based mechanisms.

**Q5.
